## 📊 Statically-Typed vs. Dynamically-Typed

| Feature | Statically-Typed | Dynamically-Typed |
|---|---|---|
| **Type Check Timing** | Compile-time | Run-time |
| **Type Mutability** | Set at compile-time; cannot change later | Determined at runtime; can change dynamically |
| **Examples** | C++, C#, Java | JavaScript, Python, Ruby |

## 🧠 What is TypeScript?

* **Superset of JavaScript:** TypeScript is JavaScript with static typing and advanced features. All valid JS is valid TS.
* **Compile-Time Checking:** Catches bugs and type mismatches at compile time before code execution.
* **Execution Flow:** Browsers and standard runtimes cannot directly execute TypeScript. The TypeScript compiler (`tsc`) transpiles TS into plain JavaScript.

```
TypeScript (.ts) ──[ Transpilation (tsc) ]──> JavaScript (.js) ──> Browser / Node.js
```

## ✅ Core Developer Benefits

* **Type Safety:** Catches bugs and mismatches early at compile time.
* **IntelliSense:** Rich IDE autocompletion, type hints, and active error detection.
* **Refactoring:** Safe code restructuring without altering behavior, verified by the compiler.

## 📝 Fundamentals & Annotations

TypeScript supports all JavaScript primitive types (`number`, `string`, `boolean`, `object`) and introduces additional type constructs (`any`, `unknown`, `never`, `tuple`, `enum`).

```ts
// 1. Primitives & Number Separators
let sales: number = 123_456_789;
let numbers: number[] = [1, 2, 3];

// 2. Tuples: Fixed-length arrays with typed positions
let user: [number, string] = [1, "Mosh"];

// 3. Functions: Explicit parameter & return types
function calculateTax(income: number): number {
  return income * 0.2;
}

// 4. Object Shapes & Method Signatures
let employee: {
  id: number;
  name: string;
  retire: (date: Date) => void;
} = {
  id: 1,
  name: "Mosh",
  retire: (date: Date) => {},
};
```

> ⚠️ **The `any` Trap:** The `any` type disables the compiler's type-checker for that variable. Avoid it wherever possible — it defeats the core purpose of TypeScript.

## 🔖 Enums vs. `as const` Objects

### Standard Enums
Used to represent a set of related constants:
```ts
enum Size { Small = 1, Medium, Large }
```

### Why Enums Break in Native Node.js (Type Stripping)
* **Type Stripping vs. Transpilation:** Modern Node.js executes `.ts` files natively by erasing types (`: string`, `interface`).
* **The Problem:** Standard `enum` and `namespace` statements are not erased — they require compilation into runtime JavaScript objects (IIFEs).
* **The Failure:** Running standard enums directly in Node.js fails with `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` because Node.js strips types but refuses to generate runtime code.

### The Modern Alternative: `as const` Object Maps
Replace standard enums with plain JavaScript objects paired with `as const`:

```ts
// 1. Define the runtime object
const Status = {
  Past: "going",
  Present: "on way",
} as const; // "as const" makes properties readonly literal types

// 2. Safely derive the TypeScript union type: 'going' | 'on way'
type StatusType = typeof Status[keyof typeof Status];

// 3. Usage remains identical to enums
function updateStatus(current: StatusType) {
  console.log(`Status is now: ${current}`);
}

updateStatus(Status.Present); // ✅ Valid & type-safe
```

> 💡 **Advantage:** 100% legal JavaScript that native Node.js can execute without transpilation, while maintaining identical autocomplete and type safety.

## 🔷 Advanced Types

### Type Alias
Create a custom name for any type — object shape, union, intersection, or primitive:
```ts
type Employee = {
  id: number;
  name: string;
  retire: (date: Date) => void;
};
```

### Union Types (`|`)
Allow a variable to hold one of many types:
```ts
let weight: number | string = 1;
weight = "1kg"; // ✅ both valid
```

### Intersection Types (`&`)
Combine multiple types into one — the value must satisfy all:
```ts
type UIWidget = Draggable & Droppable;
```

### Literal Types
Restrict a variable to a fixed set of exact values:
```ts
type Quantity = 50 | 100;         // only 50 or 100
type Direction = "left" | "right"; // only these strings
```

### Nullable Types
Explicitly allow `null` or `undefined` alongside another type:
```ts
let name: string | null = null;
```

> ⚠️ Requires `"strictNullChecks": true` in `tsconfig.json` to be meaningful.

### Optional Chaining (`?.`)
Safely access nested properties — evaluates to `undefined` instead of throwing if the chain is nullish:
```ts
customer?.birthdate?.getFullYear(); // property chain
customers?.[0];                     // array element
log?.("message");                   // function call
```

### Nullish Coalescing (`??`)
Fall back to a default only when the left side is `null` or `undefined` (not `0`, `""`, or `false`):
```ts
const speed = userSpeed ?? 30; // use 30 only if userSpeed is null/undefined
```

### Type Assertion (`as`)
Tell the compiler to treat a value as a specific type. **Does not perform runtime casting — unsafe if wrong:**
```ts
const obj = {} as Person;
```

### `unknown` Type
Type-safe version of `any`. Can hold any value but **requires narrowing before use:**
```ts
function render(document: unknown) {
  // document.trim(); // ❌ Error — can't operate on unknown directly
  if (typeof document === "string") {
    document.trim(); // ✅ Narrowed to string
  }
}
```

### `never` Type
Represents values that never occur — used on functions that never return (infinite loop or always throw):
```ts
function processEvents(): never {
  while (true) {} // never returns
}
```

## ⚙️ Tooling & Compiler Options (`tsconfig.json`)

* **Transpiling:** Translating source code from TypeScript into standard JavaScript.
* **Source Maps (`.js.map`):** Mapping files that link compiled JS back to original TS source code for debugging.
* **`tsconfig.json`:** Central configuration file defining compiler behavior and strictness.

### High-Yield Compiler Flags

| Flag | Role / Behavior |
|---|---|
| `noImplicitAny` | Warns about variables inferred as `any` when types cannot be determined. |
| `noImplicitReturns` | Ensures all code paths within a function return an explicit value. |
| `noUnusedLocals` | Reports errors for unused local variables. |
| `noUnusedParameters` | Reports errors for unused function parameters. |
| `strictNullChecks` | `null` and `undefined` are not assignable to any type unless explicitly declared as nullable. |
| `allowUnreachableCode` | When set to `false`, reports errors on unreachable code. |
| `erasableSyntaxOnly` | *(TS 5.8+)* Flags non-erasable syntax (`enum`, `namespace`) as compile errors to prevent native Node.js runtime crashes. |
| `verbatimModuleSyntax` | Enforces explicit `import type` syntax so runtime loaders know what to strip cleanly. |

#### Node.js Type-Stripping Config Example
```json
{
  "compilerOptions": {
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true,
    "target": "esnext",
    "module": "nodenext",
    "noEmit": true
  }
}
```
